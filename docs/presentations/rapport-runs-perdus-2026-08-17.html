Les deux défauts

1 — Un run ne survit pas à son hôte, et personne ne le dit

maestro/controltower/executions.py, en-tête

Un run lancé depuis la Control Tower s'exécute en tâche de fond du process maestro-api. C'est un choix assumé et écrit noir sur blanc : « un run ne survit pas au redémarrage de l'API — sa trace, elle, survit ». Retenu pour le POC parce qu'il garde l'annulation à portée sans ajouter de dépendance d'infrastructure.

Ce n'est donc pas un bug. Ce qui en est un, c'est le silence : la trace survit, l'exécution non, et rien ne distingue les deux. Le run reste « en cours » pour toujours. C'est exactement la panne traitée pour les tickets orphelins par #327 — jamais traitée pour les runs.

2 — Le stderr du CLI n'est capturé nulle part

maestro/providers/claude.py, lignes ~192 et ~271

Les deux échecs de la tâche bdd n'ont laissé que ceci, dans l'événement comme dans le journal :

Fatal error in message reader: Command failed with exit code 1 (exit code: 1)
Error output: Check stderr output for details

« Check stderr output for details » désigne un flux qui n'existe nulle part. Vérifié : le SDK installé (claude-agent-sdk 0.2.128) expose bien les champs stderr et debug_stderr — et les deux constructions de ClaudeAgentOptions du dépôt ne les passent pas. Sans rappel, le SDK n'a rien à joindre à son exception.

Conséquence : 42 minutes de travail d'agent brûlées sur deux tentatives, aucune information sur la cause — et pas même le coût, la tâche affichant 0,00 $ faute de message final.

Ce que j'ai raté

Deux erreurs de ma part, distinctes des défauts ci-dessus.

  • Les 53 minutes d'attente. Mon premier guetteur ne regardait que le compteur de tâches et le statut du run. Une validation humaine était en attente, visible dans l'UI ; je vous ai dit « rien à faire de ton côté » alors qu'une décision vous attendait. Vous l'avez trouvée seul.
  • Un « run terminé » annoncé à tort. Mon extraction du statut attrapait le dernier champ statut de la charge JSON — celui du dernier événement, pas celui du run. J'ai signalé un run fini alors qu'il tournait.

Le plan

Cinq tickets, dans le milestone Control Tower v3 — agents. Le premier est indépendant et prioritaire : sans lui, tout échec d'agent reste un échec aveugle.
